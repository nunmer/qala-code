# QALA CODE - руководство по проекту

Реализация приложения по спецификации из [README.md](./README.md).
Здесь описано, как запустить проект, как он устроен и что осталось за рамками первой версии.

---

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Сборка статической версии:

```bash
npm run build        # результат в out/
npm run preview      # локальный просмотр собранной версии
```

Проверки:

```bash
npm run verify       # типы + тесты + сборка
npm run coverage     # покрытие модулей src/lib
```

## Принятые решения

Спецификация рекомендует стек **Next.js + FastAPI + PostgreSQL/PostGIS**.
По согласованию реализован **статический фронтенд без бэкенда**:

| Требование README | Как реализовано |
|---|---|
| База данных (§6) | Типизированный датасет в `src/data/streets/`, собирается в бандл |
| API (§22) | Бэкенда нет; выборка, поиск, фильтрация и retrieval выполняются в браузере |
| PostGIS | Не требуется: 38 записей, расстояния не считаются |
| RAG (§13) | Retrieval в браузере поверх датасета, LLM - опционально |
| Админка (§25) | Редактор с рабочей копией в localStorage и выгрузкой JSON |

Следствие: приложение разворачивается на любой статический хостинг
(GitHub Pages, Vercel, Netlify, nginx) без сервера и без базы данных.

## Языки интерфейса

Русский, казахский и английский. Русский - язык по умолчанию и **язык-источник данных**.

Переключатель в шапке; выбор сохраняется в `localStorage` и применяется после
монтирования, чтобы разметка первого рендера совпадала со статически
сгенерированной.

```
src/i18n/
├── config.ts             # список языков, метки, локали
├── messages.ts           # все строки интерфейса на трёх языках
└── LanguageProvider.tsx  # контекст, хук useTranslation()
```

Тип `MessageKey` выводится из русского словаря, поэтому **пропущенный перевод -
ошибка компиляции**, а не пустое место в интерфейсе.

Содержание карточек улиц переведено отдельными наложениями:

```
src/data/streets/translations/
├── kk.ts      # казахские тексты, ключ - slug
├── en.ts      # английские тексты
└── index.ts   # getStreetText / getStreetTitle / hasTranslation
```

Если перевода записи нет, подставляется русский оригинал, **и интерфейс это
помечает** отдельной плашкой - пользователь не должен принимать подстановку
за перевод. На сегодня переведены все 38 записей; тест это проверяет.

> Казахские и английские тексты - перевод русских формулировок, новых фактов
> в них не добавлено (§14 README). Казахский текст стоит вычитать носителю языка.

## Расположение улиц: ссылка 2ГИС вместо координат

Полей `latitude` / `longitude` в базе **нет**. Расположение задаётся одним полем:

```ts
twogis_url: 'https://2gis.kz/astana?m=71.442162%2C51.16777%2F16'
```

Координаты вычисляются из ссылки (`src/lib/twogis.ts`). Это даёт три вещи:

1. расположение всегда можно проверить - открыть ту же ссылку в 2ГИС;
2. координаты не могут «разойтись» со ссылкой, потому что источник один;
3. администратор не вводит числа руками - он вставляет ссылку.

Парсер понимает все ходовые формы ссылок 2ГИС - `/geo/<id>/<lon>,<lat>`,
`?m=<lon>%2C<lat>%2F<zoom>`, ссылку на организацию - и во всех случаях читает
пару **долгота, широта** в порядке, принятом в 2ГИС.

Запись с неразбираемой ссылкой **не показывается на карте вовсе**: отсутствие
маркера честнее маркера в неверном месте. Редактор помечает такие записи
как неполные.

### Откуда взяты координаты

Из реальной геометрии OpenStreetMap, а не на глаз. Для каждой улицы взяты все
её сегменты (у магистрали их до двухсот) и усреднены их центры. Подробности и
команды - в [scripts/README.md](./scripts/README.md).

## Редактор данных (`/admin`)

### Вход

Логин `admin`, пароль `admin` (переопределяются в `.env`, см. `.env.example`).

> **Это не защита данных, и интерфейс говорит об этом прямо на форме входа.**
> Приложение статическое: проверка выполняется в браузере, учётные данные
> попадают в бандл, а весь датасет всё равно входит в состав сайта.
> Форма лишь не пускает случайного посетителя в режим редактирования.
> Для настоящего разграничения доступа нужен бэкенд с серверной проверкой.

Сессия живёт в `sessionStorage` - закрытие вкладки её завершает.

### Что умеет

- **добавить** запись (создаётся черновик со следующим свободным id);
- **редактировать** любое поле русской версии, включая подкатегории и источники;
- **удалить** запись (с подтверждением);
- **заполнить из ссылки 2ГИС** - координаты разбираются, показываются числом
  и отрисовываются на мини-карте, а название подставляется, если оно есть
  в самой ссылке (форма `/search/...`);
- **выгрузить** и **загрузить** JSON;
- **сбросить** локальные правки к версии из репозитория.

Правки хранятся в `localStorage` и сразу видны на карте, в каталоге, в AI-гиде
и на страницах улиц. Постоянного хранилища у статического приложения нет,
поэтому путь изменений в проект такой:

1. правите записи в `/admin`;
2. «Выгрузить JSON»;
3. переносите записи в `src/data/streets/*.ts`;
4. `npm run verify` - тесты проверят уникальность ключей, соответствие §29
   и то, что каждая ссылка 2ГИС разбирается и указывает внутрь Астаны.

Блок «Качество данных» показывает записи, которым чего-то не хватает.

## Раскладка под разные экраны

Проверено на ширинах 320, 375, 768 и 1280 px: горизонтальной прокрутки нет
ни на одной странице, подвал прижат к низу экрана на коротких страницах.

### Шапка

До 1024 px горизонтальное меню скрыто, вместо него кнопка с выпадающим
списком. Список позиционируется абсолютно, поэтому открытие меню не меняет
высоту шапки. Переключатель языка остаётся в строке всегда, но до 640 px
показывает двухбуквенные коды: полные подписи вместе с логотипом и кнопкой
меню не помещаются в 320 px.

### Карта

Раскладка карты принципиально разная, а не просто "сжатая":

```
широкий экран                    узкий экран
+--------+-------------+         +-------------------+
| панель |             |         | поиск | кат | спис|
| поиск  |    карта    |         +-------------------+
| фильтр |             |         |                   |
| список |             |         |       карта       |
+--------+-------------+         +-------------------+
```

Складывать панель и карту в одну колонку нельзя: панель с поиском,
фильтрами и списком из 38 записей вытесняет карту за пределы экрана, и
главный объект страницы становится недоступен. Поэтому на узком экране
карта занимает всё доступное место, а фильтры и список открываются
поверх неё и закрываются при выборе улицы. Карточка улицы там же
разворачивается на весь экран, а с 640 px становится боковой панелью.

### Высота

Высота шапки задана один раз переменной `--header-h` в `globals.css`
и оттуда же берётся полноэкранной раскладкой карты. Раньше это число
было вписано в вёрстку и не учитывало нижнюю границу шапки, из-за чего
страница карты прокручивалась на один пиксель.

Остальные страницы живут в обычном потоке: `body` растянут на
`min-h-dvh` колонкой, `main` получает `flex-1`, и подвал прижимается
к низу без вычислений.

## Оформление текста

В интерфейсе и данных не используются длинное тире, короткое тире,
типографские кавычки-лапки, фигурный апостроф, многоточие одним символом
и эмодзи. Вместо них обычный дефис, прямые кавычки и три точки.
Русские кавычки-ёлочки оставлены: это норма русской типографики.

Служебные значки (галочка, крестик) нарисованы вектором в
`src/components/Icons.tsx`, а не взяты из шрифта: глиф зависит от того,
какой шрифт нашёлся в системе, и на части устройств подставляется
цветной эмодзи вместо простой галочки.

## Поиск по разным написаниям (§8)

`normalizeForSearch` сводит кириллицу и латиницу к общему ключу:
казахские графемы приводятся к русским аналогам (ә→а, қ→к, ң→н, ө→о, ұ/ү→у, і→и),
затем результат транслитерируется и латинские варианты складываются (q→k, y→i, j→zh).

```
Кабанбай  ─┐
Қабанбай  ─┤
Qabanbay  ─┼─→  kabanbai
Qabanbai  ─┤
Kabanbai  ─┘
```

Различия настоящих согласных (Сәтбаев / Сатпаев) нормализация не склеивает -
такие пары связываются через поле `alt_names` записи.

## AI-гид: как соблюдается §14

Архитектура из §12 выполняется целиком в браузере:

```
вопрос → классификация намерения → поиск по базе → контекст → LLM → ответ
```

1. **Retrieval работает всегда.** Он определяет, какие записи вообще попадут в ответ.
2. **Модель видит только найденные записи** - больше ничего в промпт не попадает.
3. **Пустая выборка → модель не вызывается.** Возвращается фиксированная
   формулировка «данных нет» на языке интерфейса.
4. **Без ключа гид продолжает работать**: ответ детерминированно собирается из
   полей найденных записей. Формулировки проще, но фактическая часть та же.
5. **Ошибка вызова модели не скрывается**: показывается причина и ответ из базы.
6. **Каждый ответ сопровождается списком использованных записей** со ссылками.

Вопросы понимаются на всех трёх языках: ключевые слова категорий и подкатегорий
заданы по-русски, по-казахски и по-английски, а поиск идёт и по переводу,
и по русскому оригиналу.

Два нюанса, которые стоили отладки и закрыты тестами:

- ключевое слово засчитывается только в начале целого слова - казахское
  «ата**у**лар» («названия») содержит подстроку «тау» («гора») и без этой
  проверки уводило вопрос о природе в категорию географии;
- по тексту карточки ищутся только токены от четырёх символов - короткое
  слово вроде английского «are» находится внутри «area» и «Sarayshyq».

### Ключ LLM

Приложение статическое, серверного прокси нет. Ключ:

- вводится пользователем на странице `/ai` → «настроить»;
- хранится **только** в `localStorage` его браузера;
- не попадает в репозиторий и не зашивается в бандл;
- отправляется напрямую в API провайдера.

Поле Base URL принимает любой OpenAI-совместимый эндпоинт, модель задаётся строкой.

> **Для публичного развёртывания** этого недостаточно: ключ виден любому, у кого
> есть доступ к браузеру. Вызов модели нужно вынести на серверный прокси.
> Интерфейс предупреждает об этом явно.

источниками: спорные и непроверенные сведения в базу не вносились - прямое
следствие §14.

## Тесты

84 теста в `src/lib/__tests__/` покрывают логику, а не разметку:

- нормализация написаний и границы её применимости;
- поиск по казахскому, русскому, английскому и латинскому вводу;
- фильтрация по нескольким категориям;
- целостность датасета: уникальность ключей, §29, наличие названий на трёх
  языках, разбор каждой ссылки 2ГИС, попадание координат в границы Астаны,
  отсутствие совпадающих точек у разных улиц;
- корректность агрегатов «Карты смыслов»;
- retrieval: классификация намерения, отсев общеупотребительных слов,
  недопуск черновиков в выдачу, релевантность всех популярных вопросов §16
  **на каждом из трёх языков**;
- AI-гид: вызов модели, язык системного промпта, ограничение контекста
  найденными записями, поведение при ошибках API;
- разбор ссылок 2ГИС во всех формах и отказ на неразбираемых;
- демонстрационный вход и поведение при недоступном хранилище;
- наличие переводов всех записей и подстановка русского при их отсутствии.

Покрытие `src/lib`: 93% строк.

## Что не реализовано

Сознательно вне рамок (README §27 относит это к необязательному):
личные кабинеты, комментарии, социальные функции, мобильное приложение, AR,
фотографии улиц.

Требует серверной части и потому отложено:

- **Серверный прокси для LLM** - обязателен перед публичным развёртыванием.
- **Настоящая авторизация редактора** - текущая проверка демонстрационная.
- **Постоянное хранилище для админки** - сейчас правки живут в браузере
  и выгружаются файлом.
- **Полноценный REST API из §22** - эндпоинты не поднимаются, их роль выполняют
  функции `src/lib/`. Формы ответов из §22 сохранены в сигнатурах, поэтому
  перенос на FastAPI не потребует переписывать фронтенд-логику.
